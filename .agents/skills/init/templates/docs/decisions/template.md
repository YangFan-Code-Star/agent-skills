# NNNN. 标题写结论，不要写议题

日期：YYYY-MM-DD
状态：已接受 <!-- 已接受 / 已被 ADR NNNN 取代 -->

## 背景

当时面对的问题和约束。**只写决策时已知的信息**，不要用今天的后见之明改写——ADR 的价值之一就是记录"当时我们知道什么"。

## 决策

一句话说清决定了什么。然后展开必要的细节。

## 其他方案

**这一节是整份 ADR 的价值所在。** 认真考虑过的每个方案，写清它是什么，以及放弃它的**具体**原因。

只写"性能不好"、"太复杂"等于没写。要写"在 10 万行输入时需要约 40 秒，超出了单次运行 5 秒的预算"、"需要引入 X 和 Y 两个依赖，而这个项目的约束是最小依赖"。

### 方案 A：⟨名字⟩

是什么。为什么放弃。

### 方案 B：⟨名字⟩

是什么。为什么放弃。

## 后果

选了这个方案之后，带来了什么好处、什么代价、什么新的约束。

代价一定要写。每个决策都有代价，不写代价的 ADR 会让后来者以为这是免费的，从而在它开始变贵的时候不知道发生了什么。

## 什么情况下该重新考虑

具体的、可观察的信号。比如"如果数据量超过 100 万行"、"如果需要支持多用户"。

写下来，是为了让后来的 agent 知道**什么时候可以推翻它**，而不是无条件遵守一个可能已经不适用的决定。
