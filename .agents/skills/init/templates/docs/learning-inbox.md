**任务的「复盘蒸馏」写进这里，再由 `/maintain-context` 定期合并进上下文文件。**

这是一个**队列，不是档案**：条目合并后从这里**删除**，不留历史。

## 谁往这里写

主要是 `/ship-change` 的第 7 步「复盘蒸馏」。**不走 ship-change 的对话——调研、答疑、纯讨论——出现同样信号时也直接追加**，它们产生的「澄清」类信号往往是最值钱的。任务里出现的四种信号，各对应一个条目类型：

| 信号（复盘四问） | 类型 | 最终去向 |
| --- | --- | --- |
| 我一开始不懂 / 理解错了 | 澄清 | `docs/goals.md`、`architecture.md` 或 `glossary.md` |
| 用户纠正了我 | 纠正 | `AGENTS.md` 铁律（带 ❌/✅） |
| 花超过 20 分钟才搞清 | 坑 | `docs/troubleshooting.md` |
| 同一个流程/概念被解释 2 次以上 | 流程 | 新技能，或 `docs/glossary.md` |

**只有「模型猜不到、下次还会需要」的才写。** 模型本来就会的、纯单次情绪、写进文档也没用的，别往这里塞——收件箱也是要花钱合并的。

## 条目格式

每条一个 `###` 标题，标题里写清类型和日期：

```markdown
### YYYY-MM-DD 类型 — 一句话

- **现象**：当时发生了什么（我哪句说错了、卡在哪、被纠正了什么）。
- **该记住什么**：下次要遵守/知道的那句话，用可验证的措辞。
- **建议去向**：AGENTS.md 铁律 / docs/glossary.md / docs/troubleshooting.md / 新技能（名字）。
```

现象和「该记住什么」分开写：现象是证据，该记住的是结论。合并时只带走结论，现象随之删除。
