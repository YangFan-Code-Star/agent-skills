# 答案落盘映射

阶段 5 用。每个答案都有明确归属，**不要把什么都堆进 `AGENTS.md`**——它每次对话都占预算，挤掉的是读代码的空间。

## 分层原则

判断标准不是"这条信息有用吗"，而是**"它值它占的位置吗"**：

| 层 | 位置 | 什么时候进入上下文 |
| --- | --- | --- |
| 1 | `AGENTS.md` | 每次对话，全量。只放"没有它就会做错事"的内容 |
| 2 | `.agents/skills/*/SKILL.md` | 描述匹配任务时，正文才加载 |
| 3 | `docs/**` | agent 主动读取时 |
| 4 | `scripts/*.mjs` + `.agents/evals/` | 只在执行时读，几乎不占上下文 |

**能往下沉就往下沉。**

## 不要写进任何文件的内容

- **模型本来就会的东西**："要写测试"、"注意错误处理"、"遵循最佳实践"、"代码要有可读性"。纯浪费预算。
- **工具已经强制的东西**：formatter 管的缩进和引号、linter 管的未使用变量。
- **能从代码一眼读出来的东西**：函数列表、依赖清单、目录里有哪些文件。
- **真实的密钥、凭证、个人数据、生产数据样本**。需要示例时用明显虚构的值。

- [ ] `.gitignore` 覆盖了依赖、构建产物、**生成的代码**、本地数据和密钥
- [ ] `AGENTS.md`「可用技能」表里的每个技能都真实存在

## 运行时文件（不要填）

`docs/learning-inbox.md` 是任务执行中由 `/ship-change` / `/maintain-context` 维护的，不是 init 的访谈输出。初始化时**不要动它**，它带着模板自带的格式说明即可。
